## Tiny 2 bugs and solutions

- [#70](https://github.com/aaronsb/obsbot-camera-control/issues/70): confirmed against the original checkout. SDK enumeration takes seconds, but fallback ran immediately and closed discovery. Wait eight seconds before fallback, keep discovery alive, prefer SDK ownership, clear V4L2 state, and stop timers on SDK connection. Replaced the tab maximum-height cap with current-page size policies, allowing controls revealed after enumeration to lay out normally. The issue's proposal to close the SDK after detaching the callback was not copied: keeping discovery alive also permits a genuinely late SDK upgrade.
- [#33](https://github.com/aaronsb/obsbot-camera-control/issues/33) and [#44](https://github.com/aaronsb/obsbot-camera-control/issues/44): tracking commands changed autofocus, and the GUI offered no way to restore autofocus. #69 separates focus from tracking, adds an independent toggle, and restores saved auto/manual focus.
- [#41](https://github.com/aaronsb/obsbot-camera-control/issues/41): Qt activates the system numeric locale; `std::stod` then truncates dot-decimal preset values. #60 restores `LC_NUMERIC=C` after QApplication construction.
- [#56](https://github.com/aaronsb/obsbot-camera-control/issues/56), also described in [#13](https://github.com/aaronsb/obsbot-camera-control/issues/13): the export framebuffer is already measured in image pixels, but rendering scaled its viewport by the display's device pixel ratio. At 200% scaling that exports only a quarter of the picture. Apply display scaling only to the on-screen target and bind the widget's own framebuffer for on-screen rendering.
- [#57](https://github.com/aaronsb/obsbot-camera-control/issues/57): minimized/hidden Wayland windows stop receiving paint events. Export processed frames when capture delivers them, independently of visible repainting. Preserve capture/controller state while virtual output is enabled instead of disabling preview on minimize or tray hide. The hidden-frame path was tested on this machine's X11 display; a full live Wayland conferencing session remains untested.
- [#72](https://github.com/aaronsb/obsbot-camera-control/issues/72), also consistent with [#13](https://github.com/aaronsb/obsbot-camera-control/issues/13): the context-destruction callback can run during the base-class destructor after the derived GL members have been destroyed. Disconnect it in the derived destructor and verify the current context in the context-loss handler.
- [#3](https://github.com/aaronsb/obsbot-camera-control/issues/3) and [#48](https://github.com/aaronsb/obsbot-camera-control/issues/48): #69 supplies image/manual-control resets and exposure/ISO controls. ISO stays gated by a valid reported range. A successful range query alone does not establish that every Tiny 2 firmware accepts all new setter commands.

Additional integration fixes invalidate stale queued SDK callbacks and delayed UI applications, stop discovery/rescan/settling work when disconnected, prevent unrelated-device removal events from disconnecting the selected camera, respect explicit device selection, and preserve intended settings during settling. The live probe found `zoom_ratio=0` in the SDK's first status; the controller now starts at a valid 1.0× zoom while waiting for useful status.

## Validation

- GUI and CLI built successfully with the existing SDK and Qt 6.4.2.
- Final CTest run with `OBSBOT_TEST_OPENGL=1 QT_QPA_PLATFORM=xcb /usr/bin/ctest --test-dir build --output-on-failure`: **4/4 passed**, including autofocus, exposure/config, virtual-output and preview-output. In the default headless run, the optional OpenGL test correctly skips without display-test opt-in.
- OpenGL regression test ran separately with `OBSBOT_TEST_OPENGL=1 QT_QPA_PLATFORM=xcb QT_SCALE_FACTOR=2 ./build/preview-output-tests`: all four synthetic image quadrants survived export; hidden widgets emitted frames without paint events; three widget creation/destruction cycles completed cleanly. No camera frames were captured for this test.
- Read-only hardware probe: connected Tiny 2, product type 2, firmware 6.0.10.4, physical device `/dev/video2`. SDK discovery completed in about 3.6 seconds, advanced tracking controls became available, exposure/ISO range queries succeeded, callbacks ran on the controller thread, cancelled discovery stayed cancelled beyond the eight-second fallback deadline, and SDK reconnection succeeded in the same process. It did not move the camera or send camera-setting commands.
- Visible-window layout/config probe: all four tabs accommodate controls revealed after layout, without a fixed height cap; saved manual focus, exposure and ISO remain loaded, and fractional preset values survive `fi_FI.utf8`. Used an isolated config and cancelled discovery before processing camera events.
- Confirmed unattended installation into isolated `/tmp` bin/share directories produced both binaries and the desktop launcher, skipped shell-profile prompts, and required no package installation.
- Shell scripts passed `bash -n`; the final diff passed whitespace checks.

This establishes build correctness, the tested UI/output behavior, and SDK discovery on the connected Tiny 2. Live tracking movement, manual exposure/ISO changes, real v4l2loopback output through a conferencing client, other camera models, and a native Wayland session were not exercised.
